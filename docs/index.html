Basics · 1

What is a decision model?

Most AI models you have used are writers. You ask, and they write new text, one word at a time. A decision model is a chooser. You give it the possible answers, and it tells you which one fits and how likely each one is.

A huge number of everyday jobs are really about picking. Is this email urgent? Which team should get this ticket? How good is this answer, on a scale of one to five? For these jobs you do not want a paragraph. You want one clear pick that your app can act on, plus a number that says how much to trust it.

The Gemini Decisions API

The Decisions API is Google's service for asking a decision model questions. You send one request with two things: an input to look at, and a list of questions about it. You get back one answer per question.

The input is shared. If you ask three questions about one photo, the photo is sent and counted once, and all three questions read it together.

1 · Input

Anything the model should look at.

Text Image Audio Video PDF

2 · Questions

Each has an ID, a type and its possible answers.

is_scamYes / No
message_typeMultiple choice
risk_levelRubric score

3 · Answers

One per question, under the same ID.

is_scamYes · 99%
message_typedelivery
risk_level2.90 / 3

    Basics · 3
    
      
    Meet gemini-decision-1
    
      
    
        
    gemini-decision-1 is the model behind the Decisions API. Google released it on November 11, 2026. It reads your input once and scores all of your possible answers together, instead of writing an answer word by word.
    
        
    That one design choice explains most of its numbers below: it is fast, it costs nothing for output, and asking more questions about the same input barely changes the wait.
    
      
    

      
    
        
    150–250 msTypical response timeEnd to end, per Google. Time stays almost flat from 1 to 100 questions.
    
        
    1,000Questions per requestAll read the same shared input.
    
        
    256KInput tokensRoom for long documents, images, audio and video.
    
        
    $0.10Per million input tokensThe input is billed once per request, however many questions read it.
    
        
    $0For outputThe model returns scores, not written text.
    
        
    5Kinds of inputText, image, audio, video and PDF, mixed freely in one request.
    
      
    
      
    Figures from Google's launch post of November 11, 2026. Prices can change, and Google AI Studio has a free tier for trying things out. The model is available through the Gemini API and Google AI Studio, with Google Cloud support announced as coming soon.

    Decision types · 3
    
      
    Yes / No in depth
    type: "noul"
    
      
    
        
    The simplest type. You ask a question that has two sides, and the model returns one number: the chance that the answer is yes.
    
      
    
      
    
        
    You write
    One question, plus what YES and NO mean
    
        
    You get
    noul (0 to 1) and confidence
    
        
    Verdict
    Yes when noul is 0.5 or more
    
        
    Best for
    Checks, filters, flags and guardrails
    
      
    

      
    How it works
    
      
      
        
    1. You write the question as instructions, for example "Is this message a scam?"
      2. 
        
    2. You add a true_description and a false_description. They are optional, but they turn a vague word like "scam" into a clear rule the model can check.
      3. 
        
    3. The model returns noul, the chance of yes. 0.99 means "almost certainly yes". 0.12 means "probably no".
      4. 
        
    4. confidence is the chance of the side it landed on. So noul 0.12 comes with confidence 0.88. That is why a Yes / No confidence is never below 50%.
      5. 
        
    5. Your code decides what to do. The real power is that you choose the threshold. You do not have to stop at 0.5.
      6. 
      
    

      
    Pick your threshold from the cost of a mistake. If a wrong "yes" is expensive, for example deleting a real customer's comment, act only above 0.9 and send the middle to a person. If a missed "yes" is expensive, for example letting a phishing link through, act from a lower value such as 0.6.
    

      
    When to use it, and when not to
    
      
    
        
    Use it when
    
          
      
            
    • The question really has two sides: allowed or not, done or not, present or not.
      • 
            
    • You want to act on a threshold, such as auto-approve above 90%.
      • 
            
    • You need several independent checks on one input. Ask one Yes / No per check in the same request.
      • 
            
    • You want a guardrail before an expensive step, such as "Does this request need a web search?"
      • 
          
    
        
    
        
    Pick another type when
    
          
      
            
    • There is a middle ground you care about, like "somewhat urgent". Use a Rubric score.
      • 
            
    • You are choosing between named options, like billing or technical. Use Multiple choice.
      • 
            
    • You find yourself writing "and" or "or" in the question. Split it into two Yes / No questions.
      • 
          
    
        
    
      
    

      
    Real-world use cases
    
      
    
        
    Trust and safetyText
    Does this comment break our community rules?

    NO: none of these
    Hide above 0.9, send 0.5 to 0.9 to a moderator.
    
        
    SecurityText

    YES: asks for money or details through a link, or uses pressure
    NO: a genuine message
    Show a warning banner above the message.
    
        
    ProductivityEmail
    Does this email need a reply today?
    YES: asks a question or has a deadline within a day
    NO: for information only
    Pin it to the top of the inbox.
    
        
    E-commerceImage
    Does this product photo show the item on a plain background?
    YES: one item, plain light background, no text
    NO: busy scene, collage or watermark
    Approve the listing, or ask the seller for a new photo.
    
        
    Customer callsAudio
    Did the customer ask to cancel their subscription?
    YES: clearly asks to cancel or close the account
    NO: any other request
    Send the call to the retention team.

    YES: asks about recent events, prices or live data
    NO: can be answered from general knowledge
    Call the search tool only when needed, which saves time and cost.
    
      
    

      
    Pros and cons
    
      
    
        
    Pros
    
          
      
            
    • Simplest to write and to read. One question, one number.
      • 
            
    • Tunable. Move the threshold to be stricter or more relaxed, without changing the question.
      • 
            
    • Stacks well. Ten Yes / No checks on one input still use one request and share the input cost.
      • 
            
    • Clear rules. The YES and NO descriptions document your policy, so anyone can review it.
      • 
          
    
        
    
        
    Cons
    
          
      
            
    • Forces two sides. Grey areas get squeezed into yes or no. A value near 0.5 means "can't tell", not "half true".
      • 
            
    • One rule per question. Questions with "and" or "or" blur the answer.
      • 
            
    • Wording matters. Negative questions ("Is it not safe?") are easy to misread, for people and models.
      • 
            
    • No "not applicable". If the question may not apply, ask that first as its own Yes / No.
      •

    Decision types · 4
    
      
    Multiple choice in depth
    type: "choice"
    
      
    
        
    The model picks exactly one option from a list you write, and gives every option a probability. The pick tells you what to do. The probabilities tell you how close the race was.
    
      
    
      
    
        
    You write
    One question and 2 to 255 options
    
        
    You get
    choice, confidence, probabilities
    
        
    Option format
    key: description
    
        
    Best for
    Routing, tagging, intent and tool picking
    
      
    

      
    How it works
    
      
      
        
    1. You write the question, for example "Which team should handle this ticket?"
      2. 
        
    2. You list the options as keys with descriptions. The key, like billing, is what your code receives. The description, like "Payments, invoices, refunds", helps the model understand what belongs there.
      3. 
        
    3. The model spreads 100% across all options. The highest one becomes choice, and its share becomes confidence.
      4. 
        
    4. Look at the runner-up too. In the restaurant review, wait_time won at 80.5% and staff came second at 18.5%. That was a fair reading: the review complains about both the wait and the missing apology.
      5. 
      
    

      
    Use the gap between the top two. A pick at 95% with the next option at 3% is clear. A pick at 48% with the next at 44% is a coin toss, even though there is still a "winner". Measuring that gap is a simple way to send close calls to a person.
    

      
    When to use it, and when not to
    
      
    
        
    Use it when
    
          
      
            
    • Exactly one option should be true at a time.
      • 
            
    • The options are named categories with no order: teams, topics, intents, tools, document types.
      • 
            
    • Each option leads to a different code path, so the key can go straight into your routing.
      • 
            
    • You have many options. Up to 255 fit in one question, which suits tool and model routing.
      • 
          
    
        
    
        
    Pick another type when
    
          
      
            
    • Several options can be true at once, like article tags. Ask one Yes / No per tag instead.
      • 
            
    • The options have an order, like low, medium, high. A Rubric score knows that medium sits between the two.
      • 
            
    • There are only two options and they are opposites. That is a Yes / No question.
      •

    Pros and cons
    
      
    
        
    Pros
    
          
      
            
    • One pick from many, in one step. No chain of yes or no questions to narrow things down.
      • 
            
    • The full picture. Probabilities for every option show the runner-up and how close it was.
      • 
            
    • Maps straight to code. The key goes into a lookup table or a switch statement.
      • 
            
    • Easy to change. Add, rename or remove options by editing text. No training data needed.
      • 
            
    • Scales to big lists. Up to 255 options per question.
      • 
          
    
        
    
        
    Cons
    
          
      
            
    • Always exactly one answer. It cannot say "two of these apply".
      • 
            
    • Must pick something. Without an "other" or "none" option, an input that fits nothing is forced into a wrong box.
      • 
            
    • Overlaps split the vote. Similar options share probability, which lowers confidence for both.
      • 
            
    • Ignores order. To this type, "medium" is no closer to "high" than "low" is.
      • 
            
    • Long lists cost tokens. Every option and description is part of the input.
      • 
          
    
        
    
      
    

      
    Acting on the answer
    
      
    Python · route only clear wins, send close calls to triage
    

    a = answers["team"]
ranked = sorted(a["probabilities"].values(), reverse=True)
gap = ranked[0] - ranked[1]     # winner minus runner-up

if a["confidence"] >= 0.85 and gap >= 0.5:
    route_to(a["choice"])
else:
    route_to("triage")         # a close race: let a person decide

    Decision types · 5
    
      
    Rubric score in depth
    type: "score"
    
      
    
        
    Grade the input on an ordered scale that you define. Instead of one label, you get a score that can land between levels, like 1.96 on a scale from 0 to 4.
    
      
    
      
    
        
    You write
    One question and 2 to 255 levels, lowest first
    
        
    You get
    score, confidence, probabilities, legend
    
        
    Numbering
    Levels count from 0, so 5 levels give 0 to 4
    
        
    Best for
    Grading, sentiment, priority and risk
    
      
    

      
    How it works
    
      
      
        
    1. You write the question, for example "How satisfied is the guest?"
      2. 
        
    2. You list the levels from lowest to highest, each with a short description, such as "Neutral: mixed feelings". The first level is number 0.
      3. 
        
    3. The model gives every level a probability. The response also includes a legend that maps the numbers back to your level text.
      4. 
        
    4. The score is the average of the level numbers, weighted by those probabilities. That is why it can fall between levels.
      5. 
        
    5. confidence is the probability of the single most likely level. Read it next to the score.
      6.

    When to use it, and when not to
    
      
    
        
    Use it when
    
          
      
            
    • The answers have a natural order: bad to good, low to high, calm to angry.
      • 
            
    • You want to sort, rank or average many items, such as finding the 20 unhappiest reviews this week.
      • 
            
    • You want to track a trend over time, such as average satisfaction per month.
      • 
            
    • You already grade with a written rubric, as in teaching, hiring or quality checks.
      • 
          
    
        
    
        
    Pick another type when
    
          
      
            
    • The options have no order, like teams or topics. Use Multiple choice.
      • 
            
    • You only need pass or fail. A Yes / No question is simpler.
      • 
            
    • The question may not apply at all. Ask that first as a Yes / No, then score only when it applies.

    Pros and cons
    
      
    
        
    Pros
    
          
      
            
    • Respects order. Near misses stay near: "Unhappy" lands close to "Neutral".
      • 
            
    • A number you can do maths with. Sort, rank, average and chart trends.
      • 
            
    • Captures in-between cases. 1.96 says "neutral, leaning unhappy" in one number.
      • 
            
    • Your rubric is the documentation. The level text is the grading standard everyone can read.
      • 
          
    
        
    
        
    Cons
    
          
      
            
    • An average can hide a split. Always read confidence next to the score.
      • 
            
    • Order is on you. List levels lowest first, or high scores will mean the opposite of what you think.
      • 
            
    • Steps count as equal. The maths treats each step as the same size, even when your levels are not.
      • 
            
    • Starts at 0. A 1 to 5 star scale needs score + 1 in your code.
      • 
            
    • Fuzzy levels blur. Many similar levels spread probability thin. Fewer, clearly different levels work better.

    Decision types · 6
    
      
    Reading probabilities and confidence
    
      
    
        
    Probabilities spread 100% across every possible answer. Confidence is the probability of the answer the model picked. In every response we collected, confidence equals the top probability.
    
        
    Google describes the model as calibrated. That means its confidence tends to match reality: when it says 80%, it is right about 8 times out of 10. That is what lets you set a simple rule in your app, such as "act automatically above 90%, ask a person below it".

With more options it can: four options could split 40 / 30 / 20 / 10.

    When confidence is low, look closer
    
          
    For the dinner photo, the model scored healthiness at 0.59 out of 3 with only 53% confidence. It was torn between Very unhealthy (53.0%) and Unhealthy (36.3%). Both are sensible for a burger and fries. Low confidence often means your levels are close together, or the input could honestly go either way.
    
          
    The fix is usually in the question, not the model. Make the levels more distinct, or add a sentence to each one saying what it looks like.

    Using it · 1
    
      
    Strengths and limits
    
      
    
        
    The Decisions API is a specialist. It is excellent at picking from answers you can list, and it is not meant for anything else. Knowing both sides helps you design around it.
    
      
    

      
    
        
    Where it shines
    
          
      
            
    • Answers your code can trust. The answer is always one of yours, with no parsing of free text.
      • 
            
    • A number for trust. Calibrated confidence lets you automate the clear cases and review the rest.
      • 
            
    • Fast. Google quotes 150 to 250 ms, nearly flat from 1 to 100 questions.
      • 
            
    • Cheap. Output is free and the input is billed once, however many questions read it.
      • 
            
    • Multimodal. Images, audio, video and PDFs work directly. Google notes there are no separate transcription or OCR fees.
      • 
            
    • No training. Change the questions and options by editing text. There is no dataset to label.
      • 
          
    
        
    
        
    What it does not do
    
          
      
            
    • No writing. It cannot summarise, translate, reply or explain.
      • 
            
    • No extracting. It cannot pull out a price, a name or a date. Answers must be listed in advance.
      • 
            
    • No reasons. It tells you what and how sure, not why. In the playground, the line under a Yes / No verdict is your own description, not the model's explanation.
      • 
            
    • Only as good as your options. Vague, overlapping or missing options lead to weak answers.
      • 
            
    • A preview API. The playground calls it through v1beta, so field names may still change.
      • 
            
    • Still a model. It can be wrong. Keep a person in the loop for decisions that really matter.
      •

    They work well together. A common pattern is to let a writer model draft a reply, then ask the Decisions API "Is this reply safe to send?" and "How well does it answer the question?" before it reaches a customer.
    
    
    

    
    
    
      
    Using it · 2
    
      
    The Gemini Decisions Playground
    
      
    
        
    The playground is a free web app for trying the Decisions API without writing code. You add an input, build your questions, press one button and see the answers as cards. Every example in this guide was made with it.
    
      
    

      
    
        
    
          
    1
    Add your input
    In the Input & media tab, paste text, upload files, or both. Images, audio, video and PDFs all work. For images and video you can choose a resolution: more detail uses more tokens.
    
          
    2
    Write your questions
    In Decision questions, give each question a short ID, pick its type, and write the instruction. Then describe what yes and no mean, list the options, or list the rubric levels from lowest to highest. Templates in the sidebar add a ready-made question of each type.
    
          
    3
    Run
    The Run request panel ticks each check green. Press Run decisions and every question goes to the model in one request.
    
          
    4
    Read the results
    The Results tab shows one card per question with its answer, confidence and probabilities, plus tokens used and response time. Open Raw API response or download the JSON to use it in code.
    
          
    New here? Press Try an example in the sidebar to load a support ticket with three ready questions.

    Using it · 4
    
      
    For developers
    
      
    
        
    The playground uses Google's google-genai Python SDK. Here is the same call it makes, ready to copy.
    
      
    

      
    
        
    
          
    
            
            
            
          
    
          
        
    
        
    
      
    

      
    Rules to know
    
      
    
        
    type: "noul"Criteria are optional: true_description and false_description. Returns noul, the chance of yes from 0 to 1.
    
        
    type: "choice"Criteria are an object of 2 to 255 options, each key: description. Returns choice and probabilities.
    
        
    type: "score"Criteria are a list of 2 to 255 levels, lowest first, numbered from 0. Returns score, probabilities and a legend.
    
        
    input blockstext, image, audio, video or document (PDF). Files are base64 with a mime_type.
    
        
    resolutionFor image and video blocks: low, medium, high or ultra_high.
    
        
    api_version: "v1beta"The playground calls the API through the v1beta version of the Gemini API.
    
      
    
    
    

    
    
    
      
    Using it · 5
    
      
    Writing good questions
    
      
    
        
    The model can only choose well between answers that are clear. Most of the quality comes from how you write the question.
    
      
    
      
    
        
    Ask one thing at a time
    Split a double question into two. Both run in the same request, and the input is only billed once.
    Is it urgent and about billing?is_urgent + category
    
        
    Say what yes and no mean
    "Urgent" means different things to different teams. Spell it out in the YES and NO descriptions.
    Is this urgent?YES when it mentions a deadline, money lost or an escalation.
    
        
    Cover every case
    The model must pick one option, so give it somewhere to go when nothing fits.
    billing · technical · accountbilling · technical · account · other
    
        
    Keep options distinct
    Overlapping options split the probability between them and lower confidence.
    slow_service · long_waitwait_time · staff
    
        
    Order levels, and describe each one
    List rubric levels from lowest to highest, with a short sentence for each.
    Bad · OK · GoodPoor: unclear · Fair: gaps · Good: clear · Excellent: complete
    
        
    Act on confidence
    Pick a threshold. Let high-confidence answers flow through and send the rest to a person.
    Trust every answer the sameAuto-route above 90%, review below
